# ADR 0002: Keep SendLit's plan policy out of the billing tables

Status: accepted
Date: 2026-10-19

## Context

ADR 0001 kept SendLit's plan policy as `additionalFields` on the
`@codelitdev/billing` tables, plus a SendLit table with a `billing_` prefix:

- `billing_plan_states`: `plan` (never read), operator limit overrides,
  `first_paid_activated_at` (never read), and the marketing ramp.
- `billing_subscriptions`: `past_due_at` and `grace_ends_at`.
- `billing_checkout_attempts`: `pending_team_name`.
- `billing_trial_claims`.

The package allows `additionalFields` but treats them as opaque. Its
architecture says products normally keep their own data in separate tables.
MediaLit runs the package in production with no extensions. SendLit's
extensions meant writing package-owned rows (creating plan states, setting
grace on subscriptions) and reading package tables for SendLit data.
SendLit has no production users, so it can converge now.

## Decision

- The billing tables are pure package schema: `billing.config.ts` declares no
  `additionalFields`, and every `billing_` table is generated by the package.
- SendLit's policy lives in its own tables:
  - `organization_plan_policies` (one row per organization): operator limit
    overrides, the marketing ramp (`marketing_ramp_*`), and `past_due_since`.
  - `trial_claims`: one trial per person, keyed by user and by a keyed
    fingerprint of the verified email. `checkout_attempt_id` refers to the
    engine's checkout attempt without a foreign key to the package table.
  - `organizations.pending_team_name`: the first team's name for a
    `pending_payment` organization, set when it is created.
- Each feature sits on the package and Platform:
  - Paid state comes only from `commercialState`.
  - The `afterProjection` lifecycle hook records `past_due_since` when the
    entitlement subscription enters `past_due` and clears it when it leaves.
    It redeems the trial claim and creates the first team from the
    subscription's `originCheckoutAttemptId` and `payerId`, so it no longer
    reads checkout attempts.
  - The past-due sending grace is `past_due_since` plus seven days
    (`PAST_DUE_GRACE_MS`). The package keeps paid access during `past_due`;
    the grace only pauses sending.
  - Trial eligibility is decided by SendLit and passed to `startCheckout` as
    `trialDays`.
  - SendLit no longer creates `billing_plan_states` rows. The engine creates
    them when it projects a subscription.
- Quota transactions lock the organization's subscriptions, read
  `commercialState` in the transaction, then lock the plan policy row. This
  matches the engine's projection order (subscription, plan state, then the
  hook's policy write).
- Migration `0008` creates the new tables and copies the data. `0009` drops
  the extension columns and `billing_trial_claims`.

## Consequences

- `0009` is not compatible with the previous release, which still reads the
  dropped columns. This departs from the usual rule and is acceptable only
  because there are no production users. During a rollout, the old API Pod
  can fail billing reads until the new one replaces it.
- The REST API, MCP tools and dashboard are unchanged. `graceEndsAt` is now
  derived from `past_due_since`.
- SendLit still reads package tables directly where the package has no read
  model: the subscription lock order, the billing manager (payer), pending
  plan-change details, organization deletion and billing-manager blockers
  inside a transaction, billing alerts, and some operator reports. These are
  package gaps, not SendLit extensions.
