title: SequenceAnalytics
description: Show aggregate email performance metrics.
---

`SequenceAnalytics` renders aggregate delivery metrics for a broadcast or sequence.
Pair it with [`SubscriberList`](/email-blocks/subscriber-list) for the
paginated subscriber list underneath — they're separate blocks since a host
may want to show metrics without a subscriber list (or vice versa), and only
the list needs pagination.

<EmailBlockDemo demo="sequence-analytics" />

## Usage

This is the exact code behind the demo above.

```tsx
import { SequenceAnalytics } from "@sendlit/email-blocks";

const analyticsMetrics = [
    {
        label: "Subscribers",
        value: 11,
        helpText: "Contacts currently enrolled in this sequence.",
    },
    {
        label: "Emails Sent",
        value: 11,
        helpText: "Total emails delivered by this sequence.",
    },
    {
        label: "Open Rate",
        value: "18.2%",
        helpText: "Delivered emails that were opened.",
    },
    {
        label: "Click Rate",
        value: "0.0%",
        helpText: "Delivered emails with at least one tracked click.",
    },
    {
        label: "Click-to-Open",
        value: "0.0%",
        helpText: "Opened emails that also received a tracked click.",
    },
];

function Example() {
    return <SequenceAnalytics metrics={analyticsMetrics} />;
}
```

## Building the metrics

`sequenceStatsMetrics` turns a sequence's or broadcast's `SequenceStats` into
these metrics, with the same labels and help text SendLit uses. Pass the number
of contacts waiting for their next email to add a "Waiting" metric.

```tsx
import { SequenceAnalytics, sequenceStatsMetrics } from "@sendlit/email-blocks";

<SequenceAnalytics metrics={sequenceStatsMetrics(stats, schedule?.waiting)} />;
```

## Refreshing

Pass `onRefresh` to show a refresh button in the header. It spins until the
promise you return settles, so the numbers update without reloading the page.

```tsx
<SequenceAnalytics
    title="Performance"
    metrics={sequenceStatsMetrics(stats)}
    onRefresh={async () => setStats(await getSequenceStats(sequenceId))}
/>;
```

## View in browser

`ViewInBrowserSetting` is the switch for a broadcast's or sequence's
`viewInBrowser` setting, with its explanation. It saves as soon as it's
flipped: give it an async `onCheckedChange` that saves the value, and a
rejection is shown under the switch.

```tsx
import { ViewInBrowserSetting } from "@sendlit/email-blocks";

<ViewInBrowserSetting
    checked={sequence.viewInBrowser}
    onCheckedChange={async (viewInBrowser) => {
        setSequence(await updateSequence(sequence.sequenceId, { viewInBrowser }));
    }}
/>;
```
