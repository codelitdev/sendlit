`TriggerPicker` edits `triggerType` and optional `triggerData`. Host apps can
pass their own `triggers` list to add or replace the built-in trigger options.

<EmailBlockDemo demo="trigger-picker" />

## Usage

This is the exact code behind the demo above.

```tsx
import { useMemo, useState } from "react";
import { TriggerPicker, type TriggerOption } from "@sendlit/email-blocks";

function Example() {
    const [trigger, setTrigger] = useState<{
        triggerType: string;
        triggerData?: string | null;
    }>({
        triggerType: "tag:added",
        triggerData: "customers",
    });
    const [tags, setTags] = useState(["customers", "webinar", "trial"]);

    const triggers: TriggerOption[] = useMemo(
        () => [
            {
                value: "subscriber:added",
                label: "A new contact subscribes",
                needsData: false,
            },
            {
                value: "tag:added",
                label: "A tag is added to a contact",
                needsData: true,
                dataLabel: "Tag",
                valueInput: {
                    type: "select",
                    placeholder: "Select a tag",
                    options: tags.map((tag) => ({ value: tag, label: tag })),
                },
            },
            {
                value: "tag:removed",
                label: "A tag is removed from a contact",
                needsData: true,
                dataLabel: "Tag",
                valueInput: {
                    type: "select",
                    placeholder: "Select a tag",
                    options: tags.map((tag) => ({ value: tag, label: tag })),
                },
            },
        ],
        [tags],
    );

    return (
        <TriggerPicker
            triggerType={trigger.triggerType}
            triggerData={trigger.triggerData}
            triggers={triggers}
            onChange={setTrigger}
        />
    );
}
```

Omit `triggers` to fall back to the built-in list (`subscriber:added`, `tag:added`, `tag:removed`,
`event:custom` and `contact:property_changed`), where the tag triggers use a plain text input instead of
a `select`.

## Custom events and custom field changes

The `event:custom` trigger starts a sequence when a [custom event](/developers/events) with the chosen
name is received; `contact:property_changed` starts it when a contact's custom field changes. Both use a
combobox for their value that lists `valueOptions[trigger]` and accepts a typed value. For these triggers
the picker also edits `triggerFilter`: the [property filter](/email-marketing/sequences#property-filters)
for `event:custom`, or `{ from, to }` for `contact:property_changed`. `onChange` returns
`{ triggerType, triggerData, triggerFilter }`, and changing the trigger type clears the filter.

| Prop                         | Description                                                                                                   |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `triggerFilter`              | The current filter, or `null`.                                                                                |
| `valueOptions`               | Options for combobox values, keyed by trigger, e.g. `{ "event:custom": ["course purchased"] }` from `GET /events/definitions`. |
| `onCreateValue(trigger, value)` | Called when someone picks a typed value that isn't an option, e.g. to register the event with `POST /events/definitions`. |
| `eventProperties`            | Known properties of the selected event (`{ key, type }[]`), so the filter suggests keys and uses number and boolean inputs. |
| `valueFooter`                | Rendered under the value, e.g. a "no events received yet" note with a button to send a test event.            |
| `valueOptionsStatus`         | Shown above the combobox options, e.g. while they load.                                                       |
| `labels`                     | Overrides for the picker's texts (`TriggerPickerLabels`), including the filter editor's (`labels.filterEditor`). |

The filter editor is also exported on its own as `EventPropertyFilterEditor`.
